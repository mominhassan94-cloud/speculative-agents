# Speculative / early / parallel tool execution for LLM agents: core prior work

Method note: all content below was obtained via WebFetch (a small model summarizes each page), so numbers are second-hand extractions from arXiv abs/HTML pages, not read directly from PDFs (PDF text extraction failed: no pdftotext). Treat exact figures as "as reported by fetch; re-verify against the paper before citing in a write-up". Date context: November 2026.

## 1. Ye et al., Speculative Actions (arXiv 2510.04371)

### Takeaway
ID verified: arXiv:2510.04371 is "Speculative Actions: A Lossless Framework for Faster Agentic Systems" (Ye, Ahuja, Liargkovas, Lu, Kaffes, Peng; cs.AI/cs.DC/cs.MA; v1 5 Oct 2025, v2 23 Apr 2026). A fast Speculator guesses the next action(s) and pre-launches them while the slow Actor computes the real step; commit on match, discard on mismatch. Reported gains are modest in the lossless settings: up to 55% next-action accuracy and up to ~20% latency reduction (chess); e-commerce and HotpotQA report only prediction accuracy, not end-to-end latency.

### Cited Findings
- Abstract: faster models predict likely next actions, executed in parallel, committed only when predictions match; evaluated on gaming, e-commerce, web search, plus a lossy extension in an operating-systems setting; "up to 55% next-action prediction accuracy ... up to 20% latency reductions"; includes a cost-latency analysis of speculative breadth vs time savings. — [arXiv abs](https://arxiv.org/abs/2510.04371)
- ICLR 2026 status: the arXiv page lists no venue/comments; I could not confirm ICLR acceptance from the arXiv page (the task statement claims it). Gap, see below.
- Guessing: the Speculator returns k guesses for the current step; for each, it simulates next state, runs the policy to get the next call, pre-launches asynchronously and caches. Algorithm 1: on cache hit use the cached pending action; on miss the Actor's real request runs alongside the k speculative guesses. — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- Matching rules by environment: chess = Actor move equals any of top-k predicted moves; e-commerce = predicted API call matches ground-truth call; HotpotQA = exact match on both function and parameters (strict). — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- "Lossless" as defined: final trajectory matches sequential execution (chess: "the final trajectory remains identical to non-speculative play"). Enforced by semantic guards (Actor confirms state equivalence before commit), safety envelopes (only idempotent, reversible or sandboxed side effects), repair paths (rollback/compensation). Externally visible/irreversible actions need forking, snapshots or roll-forward repair. Assumes accuracy p>0 and that concurrent pre-launches are reversible or invisible. — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- Chess (TextArena): Actor GPT-5 high reasoning; Speculator GPT-5 low reasoning, speed-focused prompt, top-k moves. Metrics: prediction accuracy (rounds where any prediction matches) and time saved (T_seq - T_s)/T_seq. With 3 predictions: 19.5% average time saved, 54.7% average accuracy. The extraction notes the run count is inconsistent between caption and text (5 vs 55 runs). — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- E-commerce (tau-bench retail): 115 tasks, 15 APIs (7 write, 8 read-only). Speculator predicts user query, API calls with parameters, and number of calls. Speculators gpt-5-nano/mini/gpt-5/gemini-2.5-flash at 1024/2048/4096 reasoning budgets, single and pooled multi-model. Result: 22%-38% of API calls predicted correctly; multi-model best ~34% at ~30 s typing-time threshold; small models speculate in 2-3 s. Only accuracy reported, no measured end-to-end latency. — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- HotpotQA (ReAct; Search/Lookup/Finish): speculators GPT-5-nano, GPT-4.1-nano, Gemini-2.5-flash; strict top-k accuracy up to 46% with top-3; stronger models scored lower because phrasing variation is penalized. — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- OS tuning (lossy): sysbench CPU, Linux 5.15 on CloudLab, tuning CFS min_granularity_ns; Speculator acts every 1 s, Actor every 10-15 s, last-write-wins. p95 latency (20 s): untuned 102.97 ms, Actor-only 54.00 ms, Actor+Speculator 37.93 ms. Converges to optimum ~13 s vs ~200 s Actor-only. Cost at convergence 0.17 cents vs 2.18 cents; at matched 200 s the joint system costs 7.83 cents (higher). — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- Theory: Prop. 1 (exponential latencies, Actor rate beta < speculator rate alpha): runtime ratio -> 1 - [p(k)/(1+p(k))][alpha/(alpha+beta)], p(k)=1-(1-p)^k; max reduction 50% for breadth. Depth-focused speculation: savings (T-1)/T * p(1-b/a), ceiling 1. — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- Cost: relative cost increase = k~ - (k~ + alpha/(alpha+beta)) p(k)/(1+p(k)), k~ = distinct guesses after dedup; confidence-aware launch (Thm 4) launches branches in descending confidence while marginal gain x continuation value exceeds per-branch cost; chess heuristic keeps branches with predicted accuracy >50%, matching 3 fixed predictions on latency at lower cost. No dollar overhead figure for chess/e-commerce/HotpotQA extracted. — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- Baselines: sequential execution, Actor-only, Speculator-only, fixed breadth 1/2/3, single vs multi-model speculators. Related: speculative planning (Hua et al. 2024; Guan et al. 2025). — [arXiv HTML v2](https://arxiv.org/html/2510.04371v2)
- Code: Apache-2.0, https://github.com/naimengye/speculative-action; dirs chess-game/, e-commerce/, hotpotqa/, os-tuning/; the only bundled data is chess-game/trajectories/ (sample_trajectories, test_trajectories); config.yml holds API keys/models; 39 stars, 13 commits. — [GitHub](https://github.com/naimengye/speculative-action)

### Inferences
- The speculator here is an LLM (cheaper/faster model), so speculation costs tokens and is bounded by Speculator latency; p is low (22-55%), so gains come from k-wide breadth and cheap speculators. Tool-call prediction in a pattern/rule-based speculator (PASTE style) is a cheaper alternative.
- Hit-rate numbers are not comparable across environments: chess uses any-of-top-k move match, HotpotQA strict function+argument match, e-commerce fraction of calls matched.
- Simplest reusable pieces: strict (function, args) match as hit definition; (T_seq - T_s)/T_seq time-saved metric; the 50%-confidence branch-launch heuristic; tau-bench retail read/write API split (8 read-only vs 7 write) is a ready-made safe/unsafe classification.

### Gaps
- ICLR 2026 acceptance not confirmed by any source I fetched.
- Last ~13k characters of the HTML (appendix) unread; no extracted dollar cost overhead for the main lossless environments; chess run-count inconsistency (5 vs 55) unresolved.
- No end-to-end latency for e-commerce/HotpotQA reported.

## 2. Sui et al., PASTE (arXiv 2603.18897)

### Takeaway
ID verified but the title differs from the task statement: v1 (19 Mar 2026) was "Act While Thinking: Accelerating LLM Agents via Pattern-Aware Speculative Tool Execution"; the current v3 (16 Jun 2026) is "Parallelizing Tool Execution and LLM Generation for Low-Latency Agent Serving". Same paper, same arXiv ID (task's title wording "Act While Thinking: Pattern-Aware Speculative Tool Execution" is a close paraphrase of v1). PASTE mines recurring tool-call patterns from traces, speculatively runs predicted tool calls, and isolates results until the real call matches; headline: up to 43.5% lower average E2E latency, 1.8x lower tool latency (v3), 48.5% / 1.8x throughput in v1 abstract.

### Cited Findings
- Version history: v1 19 Mar 2026, v2 13 Jun 2026, v3 16 Jun 2026; v1 abstract: 48.5% reduction in average task completion time and 1.8x improvement in tool execution throughput; v1 introduces a "Pattern Tuple" separating control-flow context from content. — [arXiv v1 abs](https://arxiv.org/abs/2603.18897v1); [search summary](https://www.microsoft.com/en-us/research/publication/act-while-thinking-accelerating-llm-agents-via-pattern-aware-speculative-tool-execution/)
- v3 abstract: evaluated on deep research, coding and scientific-agent workloads; reduces average task completion time by 43.5%, cuts observed tool latency 1.8x. — [arXiv abs](https://arxiv.org/abs/2603.18897)
- Pattern mining: two passes. Pass 1 mines recurring short contexts over event signatures (stable control flow; volatile NL content excluded). Pass 2 checks historical occurrences to infer argument mappers (structured-field lookup, indexed result with fallback, light string normalization). Pattern record = recent event context + future tool target + argument mapper + empirical confidence; contexts keyed on tool type and success/failure status. Example motifs: search->visit (URL copied from search output), edit->run test, grep->file_editor, failed fetch -> fallback to next URL. Only patterns with high enough empirical probability kept; operator-supplied patterns validated the same way. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- Online: bounded recent-event window matched to pattern pool; only fully instantiated predictions forwarded; incomplete ones are "preparation hints" (warm-up) that never touch session state. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- Admission: executable (canonicalizable name/args), policy-safe, sufficient confidence and expected exposed-time benefit, budget headroom; invocation-level dedup; greedy by expected utility per resource. Side-effect-free fully parameterized tools run end to end; side-effecting tools only with an explicit safe policy or non-mutating variant (dry-run/staging), else not speculated. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- Match/commit: canonicalized name+args of the authoritative call compared with speculative jobs; completed match reused; in-flight match promoted (non-preemptible); else normal execution. Outcomes: reused, promoted, discarded at expiry, preempted; only reused/promoted commit. Speculative results stay outside authoritative session state until confirmed. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- Safety audit (Sec 6.8): 602 potentially side-effecting speculative actions among >20,000 speculative actions were all blocked from committing; no task's final result differed from baselines. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- Results: E2E latency average -up to 43.5%, p99 up to -55.4%; tool latency average up to -55.2%, p99 up to -60.6%; average tool speedup 1.71x over ORION and 1.83x over SpecFaaS; 97% of requests >1x; exposed tool time 34 s vs 84-89 s; LLM-side time 186 s vs 226-249 s. Scalability: >=1.27x over vLLM and >=1.24x over Agentix at each concurrency. Ablation E2E: Tool-Only 419 s, LLM-Only 342 s, Full 270 s. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- Prediction quality (Sec 6.7): Top-1 accuracy up to 27.8%; Top-3 recall up to 43.9%; overall per-call hit rate up to 93.8% (counts any speculated candidate matching). Better on structured compile/test loops, worse on open-ended research. Evaluated on tasks disjoint from the mining corpus. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- Overhead: 48% tool-latency reduction at moderate budget using 1-3 idle CPU cores and 250 MB; per second saved 0.02 core-s CPU, 2.6 MB memory, 0.9 MB network; predictor+policy <100 ms. Wasted-call rate not reported directly. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- Setup: agents VirtualLab (science), Qwen Deep Research, gemini-cli (coding); benchmarks DeepResearchBench, SWE-bench, ScholarQA; arrivals from Azure Functions trace (Shahrad et al. 2020); Qwen-DeepResearch-30B, Qwen3-30B-A3B; 32x A100-80GB on 4 nodes, vLLM; baselines vLLM, Agentix (LLM-side), ORION, SpecFaaS (tool-side). Metrics: E2E latency, observed tool latency, p95/p99, tool stall, LLM queueing, throughput, speculative hit rate, resource overhead. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)
- LLM-side co-scheduler implemented as Python startup hook in unmodified vLLM. — [arXiv HTML v3](https://arxiv.org/html/2603.18897v3)

### Inferences
- The "hit rate" 93.8% and "Top-1 27.8%" are different denominators; a student project should report both top-1 and any-candidate hit rates plus a waste ratio (speculated calls never used / total speculated), which PASTE does not report.
- The mining approach (signature n-gram contexts -> next tool + argument mapper, held out by task) is straightforward to reimplement on logged trajectories without an LLM speculator.
- PASTE's safety rule (speculate only side-effect-free, canonicalize args, keep results out of state until authoritative match) is the template to copy.

### Gaps
- No code/trace release was mentioned in the fetched HTML; not verified further. Limitations section not found in the extraction. Last ~1.2k chars unread. Which of v1 vs v3 numbers differ in setup (48.5% vs 43.5%) is not explained; cite v3 and flag the revision.

## 3. LLMCompiler, ReWOO, Conveyor and other related work

### Takeaway
LLMCompiler and ReWOO are non-speculative: plan-then-execute DAGs where parallelism is exact (no mispredictions, no waste), whereas Speculative Actions/PASTE guess calls that depend on unseen results. Conveyor overlaps tools with decoding via partial execution. 2026 has a burst of speculative-tool papers (TomasuLLM, AOSpec, Speculate with Memory, IdleSpec, Speculative Interaction Agents, Voice-agent speculation, Ghost Tool Calls), most with no linked code.

### Cited Findings
- LLMCompiler (arXiv 2312.04511, ID verified; Kim, Moon, Tabrizi, Lee, Mahoney, Keutzer, Gholami; ICML 2024): planner emits a DAG with placeholders ($1), task fetching unit dispatches ready tasks, executor runs them concurrently; dynamic replanning (Game of 24); streamed planner up to 1.3x lower latency on ParallelQA. — [arXiv abs](https://arxiv.org/abs/2312.04511); [ar5iv](https://ar5iv.labs.arxiv.org/html/2312.04511)
- LLMCompiler headline: up to 3.7x latency speedup, up to 6.7x cost savings, ~9% accuracy gain vs ReAct. Table: HotpotQA GPT-3.5 62.00% acc, 3.95 s, 1.80x; Movie Rec GPT-3.5 77.13%, 5.47 s, 3.74x; ParallelQA GPT-4-turbo 89.38%, 16.69 s, 2.15x; Game of 24 GPT-4 75.33%, 83.6 s, 2.89x vs Tree-of-Thoughts; cost reduction 3.37x HotpotQA, 6.73x Movie Rec, 4.65x ParallelQA; WebShop success 48.2% vs ReAct 19.8%. Beats OpenAI parallel function calling on latency where compared. Failure analysis: executor errors caused 64% of ParallelQA failures, planner ~8%. Text/table inconsistency: Game of 24 LLaMA 2.09x vs 2.01x. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2312.04511)
- LLMCompiler code: MIT, ~1.9k stars, includes HotpotQA, Movie Recommendation and ParallelQA benchmarks, supports OpenAI/Azure/vLLM. — [GitHub](https://github.com/SqueezeAILab/LLMCompiler)
- ReWOO (arXiv 2305.18323, ID verified; Xu et al.): decouples reasoning from observations (Planner/Worker/Solver); on HotpotQA 5x token efficiency and 4% accuracy gain; robust to tool failure; reasoning distilled from GPT-3.5 175B to 7B LLaMA. Code link not on arXiv page; not verified. — [arXiv abs](https://arxiv.org/abs/2305.18323)
- Conveyor (arXiv 2406.00059; Xu, Kong, Chen, Zhuo, Duke): tool partial execution during LLM decoding; tool-developer interface marks partial-execution points (e.g., line break/semicolon for code interpreter); up to 38.8% request completion latency improvement; negligible gains for database and calculator tools. — [arXiv/search](https://arxiv.org/abs/2406.00059)
- Dynamic Speculative Agent Planning (DSP, arXiv 2509.01920; Guan et al.): asynchronous online RL, single tunable parameter trading latency vs dollar cost; efficiency comparable to fastest lossless method, 30% total cost reduction, up to 60% reduction of unnecessary cost; code https://github.com/guanyilin428/Dynamic-Speculative-Planning. — [arXiv abs](https://arxiv.org/abs/2509.01920)
- TomasuLLM (arXiv 2609.38201; Yu et al., 22 Sep 2026): out-of-order speculative tool execution for coding agents; draft future actions, run in copy-on-write sandboxes, commit in trajectory order only after validation against committed state; 1.31x on 100 SWE-bench Verified tasks, 1.35x on 28 Terminal-Bench 2.0, 1.27x on 18 SWE-Marathon sessions; zero false accepts across 4,010 audited commit-validation records. No code link found. — [arXiv abs](https://arxiv.org/abs/2609.38201)
- AOSpec (arXiv 2608.00881; Chen, Guo, Luk, Fan): lossless action + observation co-speculation; Expected Value Decoding, isolated forks, Joint Action-State Verification (reuse only if action AND origin state match committed execution); Terminal-Bench across 4 harnesses/5 models/5 speeds: mean E2E latency -11.8% to -32.5%, p99 up to -42.8%; observation model transfers to SWE-bench Verified. No code link. — [arXiv abs](https://arxiv.org/abs/2608.00881)
- Speculate with Memory (arXiv 2607.12236; Li et al.): stateless speculators replaced by memory (contrastive transition table, episodic memory, confusion tracker); six benchmarks; relative action-prediction accuracy +19-39%, up to 2.5x on observation prediction with repetitive action spaces; search snippet says hit rate ~28% -> >50% on ALFWorld (snippet only, not on abstract page). Speculation runs in idle time so trajectory identical. No code link. — [arXiv abs](https://arxiv.org/abs/2607.12236); [search result](https://arxiv.org/pdf/2607.12236)
- Speculative Interaction Agents (arXiv 2605.13360; Hooper et al., Berkeley/Gholami-Keutzer group): async I/O + speculative tool calling for real-time (voice) agents; 1.3-1.7x speedups with minor accuracy loss on cloud models, 1.6-2.2x on 3B edge models; sensitive tools held until final confirmation (from search snippet). — [arXiv abs](https://arxiv.org/abs/2605.13360)
- IdleSpec (arXiv 2605.22154): speculative planning (not tool execution) during tool idle time; GAIA/FRAMES 55.6% avg accuracy with Gemini-2.5-Flash (+5.1%), MLE-Bench up to +9.1% Any Medal. — [arXiv abs](https://arxiv.org/abs/2605.22154)
- Voice agents (arXiv 2610.07641): tool calls predicted from partial ASR hypotheses; median time-to-first-audio 5.79 s -> 4.60 s; rule-based validation of cached results; worst-case bounded by serial baseline. — [arXiv abs](https://arxiv.org/abs/2610.07641)
- Ghost Tool Calls (arXiv 2606.02483, cs.CR): speculative calls leak inferred intent even if abandoned; only issue-time policies (alter/suppress args or destination before dispatch) reduce it, not post-hoc filters, read-only restriction or allow-lists; 12 policies, 3 corpora. — [arXiv abs](https://arxiv.org/abs/2606.02483)
- Speculative decoding (Leviathan et al. 2023) and processor speculation (Tomasulo 1967) are the cited inspirations of Speculative Actions. — [PDF metadata via fetch](https://arxiv.org/pdf/2510.04371)

### Inferences
- LLMCompiler/ReWOO need no hit-rate metric (no speculation); their "correctness" is task accuracy vs ReAct, and "cost" is token/dollar cost ratio. Speculative papers add hit rate, wasted calls and commit-correctness (lossless audits: PASTE 602 blocked, TomasuLLM 0 false accepts in 4,010).
- Metric definitions differ: Speculative Actions (accuracy of top-k), PASTE (top-1, top-3 recall, any-candidate hit), AOSpec (action+state match), Speculate with Memory (relative accuracy gain).
- A student project could combine: PASTE-style pattern mining as speculator, strict canonical (name,args) matching, read-only-only speculation, and report hit rate, waste ratio, time saved, and final-answer equivalence.

### Gaps
- Not fetched: Speculative RAG (Wang et al. 2024), Skeleton-of-Thought, Parrot/Autellix/Continuum/InferCept/Agentix, ORION, SpecFaaS, OpenAI/Anthropic parallel function-calling docs; ReWOO code and per-benchmark latency; LLMCompiler appendix ablations. Search for Speculative RAG/SoT returned nothing.
- Several 2026 IDs were verified only through the fetch tool's page summaries; full texts unread.

## 4. Open-source code, trajectories and datasets reusable by a student project

### Takeaway
Only Speculative Actions (Apache-2.0, small), LLMCompiler (MIT, ~1.9k stars) and DSP have confirmed repos. No released trajectories/traces were found for PASTE, TomasuLLM, AOSpec, Speculate with Memory. Public benchmarks used by these papers are the realistic data source.

### Cited Findings
- Speculative Actions repo with chess trajectories only (sample_trajectories, test_trajectories); e-commerce/HotpotQA/OS code but no described data. — [GitHub](https://github.com/naimengye/speculative-action)
- LLMCompiler repo: HotpotQA, Movie Rec, ParallelQA datasets bundled. — [GitHub](https://github.com/SqueezeAILab/LLMCompiler)
- DSP repo. — [GitHub](https://github.com/guanyilin428/Dynamic-Speculative-Planning)
- Public benchmarks used across papers: tau-bench retail, HotpotQA, TextArena, SWE-bench (Verified), Terminal-Bench (2.0), GAIA, FRAMES, MLE-Bench, ALFWorld (via search snippet), DeepResearchBench, ScholarQA, WebShop, Azure Functions trace for arrival times. — sources as cited in sections above.

### Inferences
- Cheapest reproduction path: collect own ReAct/tau-bench or SWE-bench trajectories, mine patterns offline, replay speculation against logged traces (no live API cost).

### Gaps
- Repo existence for PASTE, TomasuLLM, AOSpec, Speculate with Memory, IdleSpec, Conveyor not confirmed (no link on abs pages); a GitHub search was not done.
