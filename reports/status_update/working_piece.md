## 1. Speculator alone (`python spec_demo.py`)

Model: `gemini-3.5-flash-lite`

### Prompt (system instruction)
```
You predict the NEXT tool call an AI agent will make, so it can be started early.

You are given the user's task, the tools available, and the calls made so far with their results.
Predict the single most likely next tool call, with exact arguments copied from the data above
(do not invent values). If the agent is probably finished, or you cannot predict exact arguments,
return null for tool.

Reply with ONLY JSON, no other text:
{"tool": "<tool name or null>", "args": {...}, "confidence": <0.0-1.0>}
```

### Input (user message sent to the model)
```
TASK: Find the nonstop flights from Houston (IAH) to Denver (DEN) on 2026-11-06 and compare their total cost including checked-bag fees.

TOOLS:
- search_flights(origin, dest, date): Search nonstop and connecting flights between two airports on a date.
- get_fare_details(flight_id): Get baggage fees and fare rules for one flight.
- search_web(query): Search the web. Returns a list of result links.
- open_page(url): Open a web page by URL and return its text.
- get_weather(city, date): Get the weather forecast for a city and date.
- lookup_airport(code): Look up an airport by IATA code.
- get_calendar(date): Read the user's calendar for a date.
- book_flight(flight_id): BOOK a flight (charges the user). Side effect.
- send_email(to, body): SEND an email. Side effect.

CALLS SO FAR:
1. search_flights({"origin": "IAH", "dest": "DEN", "date": "2026-11-06"}) -> {"flights": [{"flight_id": "UA482", "airline": "United", "price": 189, "nonstop": true}, {"flight_id": "WN219", "airline": "Southwest", "price": 204, "nonstop": true}, {"flight_id": "F9133", "airline": "Frontier", "price": 142, "nonstop": true}, {"flight_id": "AA907", "airline": "American", "price": 231, "nonstop": false}]}

Predict the next call.
```

## 4. Numbers at a glance

| Speculator | Baseline s | Spec. s | Faster | Launched | Hits | Wasted | Too late | Tool s saved | 429s | Same calls |
|---|---|---|---|---|---|---|---|---|---|---|
| LLM (gemini-3.5-flash-lite) | 10.2 | 10.2 | 1% | 2 | 1/3 | 1 | 2 | 0.16 | 0 | yes |
| Rules | 10.5 | 8.4 | 20% | 3 | 3/3 | 0 | 0 | 2.03 | 0 | yes |

Notes:

- One run per configuration (n=1). Gemini latency varies by a few tenths of a second per call, so small differences are within noise.
- *Hits* = correct guesses out of the calls that could be speculated (every call after the first). *Too late* = the guess arrived after the agent had already made that call, so it was dropped instead of run. *Wasted* = speculative tool runs whose result was never used.
- *Tool s saved* is the runtime's own estimate (tool time minus time spent waiting on the hit); end-to-end differences also include Gemini latency variation.
- The final answers are worded differently between runs (Gemini sampling), but the tool-call sequence and the cost figures they report are the same.
- Gemini requested several `get_fare_details` calls in a single turn (parallel function calling). The agent loop runs one tool per step, so it executes the first call and the model asks again for the rest next turn.
- 429 handling was exercised in an earlier run (`logs/pre-fix/demo-llm-rules-20261101-233601.txt`): 4 rate-limit retries, 30.8s of backoff, after which the run completed. That run is excluded from the timing numbers because the backoff inflated its baseline.
